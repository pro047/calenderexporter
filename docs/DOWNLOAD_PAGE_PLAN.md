# 쉬운 앱 다운로드 페이지 제작 계획

## 1. 목표

GitHub를 모르는 사용자도 링크 하나를 눌러 `한 달 일정 보내기` 앱을 내려받고
설치할 수 있는 모바일 우선 안내 페이지를 만든다.

완성된 페이지는 카카오톡으로 주소 하나만 전달할 수 있어야 하며, 로그인이나
회원가입을 요구하지 않는다.

예상 공개 주소:

```text
https://pro047.github.io/calenderexporter/
```

## 2. 주 사용자

- 50~70대 안드로이드 휴대폰 사용자
- GitHub, APK, SHA-256 같은 용어에 익숙하지 않은 사용자
- 삼성 인터넷 또는 Chrome으로 카카오톡 링크를 여는 사용자
- 작은 글씨와 여러 선택지가 부담스러운 사용자

## 3. 제작 원칙

- 첫 화면에는 가장 중요한 `앱 다운로드하기` 버튼 하나만 크게 표시한다.
- 본문 글씨는 18px 이상, 주요 버튼 높이는 60px 이상으로 만든다.
- GitHub, Release, APK 같은 개발 용어는 일반 안내에서 사용하지 않는다.
- 한 문장은 짧게 쓰고 한 단계에는 한 가지 행동만 안내한다.
- 설치가 막힐 때의 자세한 내용은 접어 두고 필요할 때만 펼친다.
- 색만으로 의미를 구분하지 않고 글과 번호를 함께 사용한다.
- 광고, 방문자 추적, 로그인, 개인정보 입력 기능을 넣지 않는다.

## 4. 화면 구성

### 상단

- 앱 아이콘
- `한 달 일정 보내기`
- `안드로이드용 · 버전 0.1.2`

### 핵심 영역

- 제목: `한 달 일정을 한 번에 파일로 만드세요`
- 설명: `휴대폰 일정표에서 원하는 달을 골라 텍스트 파일이나 메시지로 보낼 수 있습니다.`
- 큰 버튼: `앱 다운로드하기`
- 보조 안내: `안드로이드 8 이상 휴대폰용 · 약 1.8MB`

표시할 파일 크기는 공개된 APK의 실제 크기를 확인한 뒤 확정한다.

다운로드 버튼은 현재 공개된 다음 파일에 연결한다.

```text
https://github.com/pro047/calenderexporter/releases/download/v0.1.2/month-calendar-exporter-v0.1.2.apk
```

### 안심 안내

- `일정을 읽기만 하고 바꾸거나 지우지 않습니다.`
- `앱이 일정을 자동으로 인터넷에 보내지 않습니다.`
- `필요한 파일은 휴대폰 안에서 만듭니다.`
- `파일을 보낼 앱과 사람은 사용자가 직접 선택합니다.`

### 설치 3단계

1. 파란색 `앱 다운로드` 버튼을 누른다.
2. 받은 파일을 열고 `설치`를 누른다.
3. 앱을 열고 `일정 읽기 허용`을 누른다.

### 설치 도움말

`설치가 안 될 때 보기` 버튼을 누르면 다음 내용을 펼친다.

1. 다운로드가 시작되지 않으면 카카오톡 오른쪽 위 메뉴에서 `다른 브라우저로 열기`를
   선택한다.
2. 설치 차단 화면에 나온 `설정`을 누른다.
3. 다운로드에 사용한 인터넷 앱의 `이 출처 허용`을 켠다.
4. 위 방법으로도 설치되지 않는 삼성 휴대폰에서만
   `설정 → 보안 및 개인정보 보호 → 자동 차단`을 설치할 때 잠시 끈다.
5. 설치가 끝나면 `이 출처 허용`과 자동 차단 설정을 원래대로 되돌린다.

설정 이름은 휴대폰 모델과 Android 버전에 따라 다를 수 있다고 함께 안내한다.
자동 차단 해제는 보안 기능을 끄는 행동이므로 마지막 수단임을 명확히 표시한다.

## 5. 제작 방식

- 저장 위치: `docs/index.html`
- 추가 파일이 필요하면 `docs/assets/` 아래에 둔다.
- 별도 웹 프로그램이나 서버 없이 HTML, CSS, 최소한의 JavaScript만 사용한다.
- 외부 글꼴과 분석 도구를 사용하지 않아 느린 환경에서도 빠르게 연다.
- GitHub Pages 게시 원본은 `main` 브랜치의 `/docs` 폴더로 설정한다.
- 모든 주소는 HTTPS를 사용한다.

## 6. 마일스톤

### M1. 화면 제작

- 모바일 화면을 기준으로 `docs/index.html` 제작
- 큰 글씨, 큰 버튼, 짧은 문장 적용
- 설치 도움말 펼치기와 닫기 구현

### M2. 기본 화면 검증

- 너비 360px, 412px, 736px에서 잘림과 겹침 확인
- 휴대폰의 큰 글씨 설정에서도 핵심 버튼과 문구 확인
- 키보드만으로 버튼을 선택할 수 있는지 확인
- 텍스트와 배경의 명암 대비가 4.5:1 이상인지 확인
- 화면을 200% 확대해도 내용이 잘리거나 가로 스크롤이 생기지 않는지 확인
- 키보드 포커스 위치가 눈에 보이는지 확인
- 설치 도움말은 JavaScript가 없어도 작동하는 `<details>`와 `<summary>`로 구현

### M3. 다운로드 연결

- `앱 다운로드하기` 버튼을 실제 APK에 연결
- 로그인하지 않은 상태에서 다운로드 응답 확인
- 공개 APK의 실제 파일 크기를 확인하고 화면 표시와 일치시킴
- SHA-256이 `docs/INSTALL.md`의 확인값과 일치하는지 확인
- APK 내부 버전이 화면에 표시한 버전과 일치하는지 확인
- APK가 올바른 배포용 서명 열쇠로 서명되었는지 확인

### M4. GitHub Pages 공개

- 저장소 `Settings → Pages`에서 `Deploy from a branch` 선택
- `main`과 `/docs` 폴더 선택
- 공개 주소에서 HTTPS 접속 확인

### M5. 실제 사용자 흐름 검증

- 삼성 인터넷에서 카카오톡 링크 열기
- Chrome에서 카카오톡 링크 열기
- 카카오톡 내부 화면에서 다운로드가 막힐 때 `다른 브라우저로 열기` 안내 확인
- 다운로드, 설치 허용, 앱 실행까지 순서대로 확인
- 실제 사용자가 안내를 읽지 않고도 핵심 버튼을 찾는지 확인

### M6. 전달 자료 제작

- 카카오톡용 한 문장 안내 작성
- 페이지 주소 QR코드 제작
- 설치가 막힐 때 연락할 사람 또는 연락 방법 결정

## 7. 완료 기준

- 처음 방문한 사용자가 5초 안에 다운로드 버튼을 찾을 수 있다.
- 첫 화면에 다운로드 버튼이 스크롤 없이 보인다.
- 다운로드 버튼을 누르면 올바른 APK가 내려받아진다.
- 지원 조건이 `안드로이드 8 이상`으로 명확히 표시된다.
- 어려운 개발 용어를 몰라도 설치 순서를 이해할 수 있다.
- 삼성의 설치 차단 상황에서 도움말만 보고 다음 행동을 알 수 있다.
- 카카오톡 내부 화면에서 다운로드가 막혀도 다른 브라우저로 여는 방법을 알 수 있다.
- 페이지가 사용자 정보나 일정 내용을 수집하지 않는다.
- 휴대폰과 PC 화면에서 가로 스크롤이 생기지 않는다.
- 화면을 200% 확대하거나 큰 글씨를 사용해도 핵심 버튼과 문구가 잘리지 않는다.
- 키보드만으로 모든 링크와 도움말을 사용할 수 있고 포커스 위치가 보인다.

## 8. 새 버전 배포 절차

새 앱 버전이 나올 때마다 다음 순서를 지킨다.

1. 같은 배포용 서명 열쇠로 새 APK를 만든다.
2. 실제 기기에서 기존 앱 위에 설치되는지 확인한다.
3. GitHub Release에 새 APK를 올린다.
4. 새 APK의 파일 크기, SHA-256, 내부 버전과 서명을 확인한다.
5. `docs/index.html`의 버전, 파일 크기, 다운로드 주소를 바꾼다.
6. `docs/INSTALL.md`의 버전과 SHA-256 확인값을 바꾼다.
7. 저장소에서 이전 버전과 이전 다운로드 주소가 남아 있는지 검색한다.
8. 로그인하지 않은 상태의 공개 페이지에서 다운로드를 다시 확인한다.
9. 카카오톡 안내와 QR코드는 같은 페이지 주소를 계속 사용한다.

배포용 서명 열쇠와 비밀번호 파일은 GitHub에 올리지 않는다.

## 9. 이번 범위에서 제외할 기능

- 회원가입과 로그인
- 방문자 분석과 광고
- 앱 내부 자동 업데이트
- 기종 자동 감지
- 일정 또는 사용 기록 서버 전송
- 여러 버전을 고르는 복잡한 다운로드 목록
