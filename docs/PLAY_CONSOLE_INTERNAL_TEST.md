# Google Play 내부 테스트 등록 순서

## 준비된 파일

- 업로드 번들: `dist/month-calendar-exporter-v0.1.2.aab`
- SHA-256: `dist/month-calendar-exporter-v0.1.2.aab.sha256.txt`
- 스토어 문구: `docs/STORE_LISTING_KO.md`
- 개인정보처리방침: `https://pro047.github.io/calenderexporter/privacy.html`

## 1. 앱 만들기

Play Console에서 **모든 앱 → 앱 만들기**를 연다.

- 기본 언어: 한국어(대한민국)
- 앱 이름: 한 달 일정 보내기
- 앱 또는 게임: 앱
- 무료 또는 유료: 무료

처음 업로드한 뒤에는 패키지 이름 `io.github.pro047.calendarexporter`를 바꿀 수 없다.

## 2. 내부 테스트 출시 만들기

**테스트 및 출시 → 테스트 → 내부 테스트 → 새 버전 만들기**에서 다음 AAB를 업로드한다.

```text
dist/month-calendar-exporter-v0.1.2.aab
```

- 출시 이름: `0.1.2-internal-1`
- 출시 노트: `docs/STORE_LISTING_KO.md`의 내부 테스트 출시 노트 사용
- Play 앱 서명: 사용

새 앱의 첫 AAB이므로 Play 앱 서명에서 Google이 앱 서명 키를 관리하도록 두고,
현재 로컬 키는 이후 번들을 올리는 **업로드 키**로 계속 보관한다. 로컬 키를 잃으면
업로드 키 재설정 절차가 필요하므로 `.secrets/calendar-exporter-release.jks`를 별도 백업한다.

## 3. 테스터 추가

**내부 테스트 → 테스터**에서 이메일 목록을 만든다.

- 목록 이름 예시: `calendar-exporter-internal`
- 테스터가 Play 스토어에서 사용하는 Google 계정을 입력한다.
- 의견 수렴 주소: `https://github.com/pro047/calenderexporter/issues/new`

변경사항을 저장한 뒤 표시되는 참여 링크를 테스터에게 보낸다. 내부 테스트는 최대
100명까지 가능하며 12명·14일 조건은 적용되지 않는다.

## 4. 앱 콘텐츠 답변

현재 0.1.2 구현을 기준으로 입력한다.

- 광고 포함 여부: **아니요**
- 앱 액세스: **모든 기능을 제한 없이 이용 가능** — 로그인 없음
- 타겟 연령: **만 18세 이상** 권장
- 뉴스 앱: **아니요**
- 건강 앱: **아니요**
- 정부 앱: **아니요**
- 금융 기능: **없음**
- 개인정보처리방침 URL: `https://pro047.github.io/calenderexporter/privacy.html`

콘텐츠 등급 설문은 유틸리티/생산성 앱의 실제 기능대로 답한다. 폭력, 성적 콘텐츠,
도박, 욕설, 사용자 간 콘텐츠 교환, 구매 기능은 없다. 앱은 사용자가 다른 앱으로
텍스트를 보내도록 Android 공유 화면만 연다.

## 5. Data Safety 답변

현재 앱은 인터넷 권한과 분석 SDK가 없고, 일정 데이터를 기기 안에서만 처리한다.
또한 다른 앱으로의 전달은 사용자가 공유 버튼을 누른 뒤 대상을 직접 고르는 동작이다.
Google의 Data Safety 정의상 기기 내 처리와 명시적인 사용자 시작 공유는 수집·공유
신고 대상에서 제외될 수 있으므로 현재 빌드의 권장 답변은 다음과 같다.

- 앱이 필수 사용자 데이터 유형을 수집하거나 공유하나요?: **아니요**
- 모든 사용자 데이터가 전송 중 암호화되나요?: 데이터 전송 없음
- 사용자가 데이터 삭제를 요청할 수 있나요?: 계정 및 서버 저장 데이터 없음

캘린더 접근 자체는 개인정보처리방침과 앱의 권한 안내에 명시한다. 향후 인터넷 권한,
분석 SDK, 충돌 보고, 광고, 계정 또는 서버 저장을 추가하면 이 답변을 다시 작성한다.

## 6. 일정 권한 설명

Play Console에서 권한 사용 목적을 묻는 경우 다음 문구를 사용한다.

```text
사용자가 선택한 달의 일정을 휴대폰 캘린더에서 읽어 화면에 표시하고,
카카오톡·문자 메시지 본문 또는 TXT 파일로 정리하는 앱의 핵심 기능에 사용합니다.
일정은 사용자가 버튼을 누른 경우에만 읽으며 기기 안에서 처리됩니다.
기존 일정을 생성·수정·삭제하지 않고 자체 서버로 전송하지 않습니다.
```

## 7. 출시 전 확인

1. 공개 개인정보처리방침 URL이 로그인 없이 열리는지 확인한다.
2. 지원 이메일을 실제 수신 가능한 주소로 입력한다.
3. 테스터 Google 계정이 목록에 포함됐는지 확인한다.
4. AAB의 버전 코드가 `3`, 버전 이름이 `0.1.2`인지 확인한다.
5. 내부 테스트 버전을 게시하고 참여 링크로 Play 스토어 설치를 확인한다.

내부 테스트 앱은 처음 최대 48시간 동안 임시 앱 이름과 임시 등록정보가 표시될 수 있다.
이후 프로덕션 출시를 준비할 때는 Data Safety, 스토어 등록정보와 콘텐츠 등급을 다시
최종 점검한다.
